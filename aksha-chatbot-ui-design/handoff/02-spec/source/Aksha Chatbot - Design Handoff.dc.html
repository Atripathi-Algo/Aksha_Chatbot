Aksha support chatbot — UI design handoff

Specification for the in-app support chatbot panel: container, message-type ladder, agent attribution, rich output types, evidence and trust affordances, degraded states, responsive behaviour and accessibility. Built as an evolution of the existing ChatPopover.tsx, MUI v5, light theme only.

Design source of truth: option 3a (ruled ledger) with the agent and chart work from 4a–4c. Anything not stated here is deliberately left to engineering discretion.

1 · Decisions and rationale

DecisionWhat we choseWhy
ContainerDocked right-hand side panel, 420px, full height; overlays only the rightmost dashboard columnOperators watch live feeds while asking. A floating popover occludes tiles and is too small for cited answers; full-screen breaks monitoring.
LauncherDocked right-edge tab, 40px, with an unread dotA floating action button always lands on top of a camera tile.
Message layoutFlush-left ledger rows separated by 1px rules; no chat bubbles for assistant repliesAnswers carry tables, charts and frames — a bubble constrains them. Role and freshness live on a meta line above each message.
Weight ladderVisual weight rises with consequence; only the approval type gets a solid accent bandOperators must be able to spot a state-changing request at a glance without reading.
DensityCalmer than the dashboard: 16px gutters, 13.5px body, one accentThe panel's job is to reduce cognitive load, not add another dense surface.

2 · Panel shell

Four fixed regions, top to bottom:

RegionSpec
Header48px, neutral-100 ground, 2px ink bottom rule. 22px brand mark, "AKSHA ASSISTANT" at 11px/700, letter-spacing .14em. Right: Agents disclosure (chevron-down), Download, close (Lucide x, 15px).
Scope stripOptional. Active context chips (camera, date, severity) with per-chip dismiss (Lucide x, 11px) and a Clear action. Present whenever the conversation carries implicit scope; hidden when empty.
Message listScrolling flow, one padded row per message, 1px divider between rows. Auto-scrolls only when already pinned to the bottom.
Composer2px ink top rule, neutral-100 ground. Input line, language segmented control (EN / हिं / मर), primary Send. Send is 32px tall minimum; on touch viewports 44px.

Empty state

Display line ("Ask instead of navigating."), one sentence of capability, then exactly three clickable example questions as full-width rows with a trailing arrow. No wall of text, no capability list.

3 · Message-type ladder

Seven types. The left marker and fill are the entire encoding — nothing else changes.

TypeTreatmentContains
Operator messagesurface fill, 2px ink left ruleText only, any script
Answer2px divider left rule, no fillProse, optional table / chart / frames, citation chips, freshness label
Streaming2px accent left rule + 2px animated progress bar; block caret at the text headPartial prose, "sources resolving · n of m", Stop action
Clarification2px accent box on accent-100; header "NEEDS YOUR ANSWER"Question + 2–3 full-width option buttons
Degraded1px neutral-600 box on neutral-200; header "PARTIAL ANSWER"What failed, what still works, correlation ref, Retry / Copy ref
EscalationAnswer rule + captured-detail tableTicket, camera, alert, description; Edit details / View ticket
Approval (future)2px ink box, solid accent band, expiry countdownAction statement, consequence line, Approve / Reject (full width, flush-left labels)

Rule

Approval is the only type allowed a solid accent field, because it is the only one that changes system state. Ship it visually de-emphasised (85% opacity, disabled actions) until the backend exists — do not invent a second red-field type.

4 · Agents

Every answer names the agent that produced it. The badge replaces the generic role label in the same position and size, so the ledger rhythm is unchanged. API-backed agents get an accent-tinted badge; chatbot-layer agents a neutral one and no freshness label, since they read nothing live.

AgentReadsBadge / notes
Help & Product GuideIndexed docs / UserManualNeutral badge; cites a manual section, shows doc version
Alert Investigation (basic)/api/alert · /api/myAlertAccent badge; alert-ID chips + frames
Camera Operations/api/camera · /api/camgroupAccent badge; usually a table answer
Live Monitoring/api/active · Socket.IOAccent badge; freshness reads "Socket · n s ago"
Insights & Analytics/api/insight · /api/insightReportAccent badge; bar / pie / table + date-range label
Notification (read)/api/notificationAccent badge; delivery status, never sends mail itself
Multi-Language SupportChatbot layer onlyNeutral badge with language code; phrases another agent's result — footer states both
Error Code ExplanationChatbot layer onlyNeutral badge; mono code header + plain-language cause block

Directory. The header's Agents disclosure opens a two-column grid of all eight, each with its endpoints in mono. Accent-200 tiles read live endpoints; plain tiles answer from the chatbot layer. It is informational — routing is automatic; a manual override is out of scope for phase one.

Multi-agent answers. When several agents contribute, the badge collapses to "n agents" with their names beside it and the answer is presented as one labelled fact list (Alert / Delivery / Meaning) — never as several separate replies.

5 · Rich output types

All rich output shares one container: 1px ink box, header strip with the title and an export action, footer naming the endpoint and range. Series colours are accent ramp steps only — 800 / 500 / 200 — so charts stay mono and remain legible printed in grayscale.

TypeSpecRules
TableDesign-system .table, 11.5px, header row repeats; max 5 rows inline with "showing 5 of n"Expand opens the full result in the Alerts/Cameras screen. CSV export. Never horizontally scroll — drop columns instead.
Bar chartHorizontal bars, 14px tall, 96px label gutter, value flush right; track neutral-200Horizontal so camera names stay readable. Max 6 bars inline; more goes to a report link. Always print the value — the bar is secondary.
Pie / donut110px inline SVG donut, 22px stroke, no rounded caps; legend right with label, count and percentMax 4 segments; a fifth becomes "Other". Legend, not labels-on-slices. role="img" with a summarising aria-label.
Frames16:9, 180–200px wide, 1px ink border, grayscale, caption strip with alert ID and timeOne per cited alert, max two side by side; click opens the alert in review. Grayscale per the imagery rule.

6 · Evidence, freshness, language

ElementSpec
Citation chips1px ink border, 10px/600 label, zero radius, indented to the answer's text column under a "SOURCES" kicker. Content: alert ID + time, camera name, or document section. Hover inverts to ink fill. Cached answers use a dashed border.
Freshness labelRight end of the meta line, above the answer — a different band from the citations, so the two never compete. Three forms: filled dot + "LIVE · hh:mm:ss"; hollow dot + "CACHED · LAST KNOWN hh:mm"; agent-specific "SOCKET · n s ago". Cached answers also carry a Retry live action.
Endpoint readMono, neutral-700, beside the citation chips. Informational for operators, diagnostic for support.
Mixed scriptBody line-height rises from 1.6 to 1.75 for Devanagari. Camera names, alert IDs and timestamps stay Latin, marked with a 2px accent underline and white-space: nowrap so they never break mid-identifier.

ViewportBehaviour
≥ 1100pxDocked side panel, 420px, full height.
600–1100pxBottom sheet at 64% viewport height with a drag handle (40% / 64% / 88% stops). At least two camera tiles stay visible — deliberately not a full-screen overlay.

8 · Accessibility

AreaRequirement
Open / closeAlt+K toggles the panel from anywhere; focus lands on the input. Esc closes and returns focus to the launcher tab. Focus is trapped in the panel only when it is a full-screen overlay.
Tab orderScope chips → message list (one stop per message, arrow keys move between messages) → frames → citation chips → composer → Send. Clarification options and Approve/Reject are real buttons in DOM order; Approve is never the first focus stop.
StreamingThe streaming region is aria-live="off". A separate polite region announces "Answer in progress" once, then the complete answer plus "n sources" on stream end. Never announce per token. Offer a "read as it arrives" preference that switches to aria-live="polite" chunked by sentence.
Chartsrole="img" with an aria-label stating the summary in words; the legend's counts and percentages are real text, and every chart's headline figure also appears in the answer prose.
ContrastInk #1b2029 on #f4f5f7 = 14.1:1. Accent #326BC9 on the ground = 4.6:1 — passes AA for the 10px chip and label text and for white-on-accent bands. Freshness labels use neutral-700 (5.1:1); do not lighten. Focus is a 2px accent :focus-visible ring at 2px offset — never the browser default.

10 · Open questions

  1. Does the operator ever need to force a specific agent, or is automatic routing enough for phase one?
  2. Frames: served from the alert record directly, or fetched on demand when the answer renders? Affects panel load time.
  3. Retention — how long does a conversation persist, and does Download capture frames and charts or text only?
  4. Approval: which actions will be in scope first, and who authorises them (operator vs site administrator)?
  5. Escalation target — existing ticketing system, or a new support queue?
