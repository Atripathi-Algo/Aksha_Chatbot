Backend, database, and chatbot tool architecture

A ground-truth map of what actually runs today — traced from aksha-chatbot-api and docs/CHATBOT_SYSTEM_ARCHITECTURE.md, not the target design.

Database is MongoDB — not ChromaDB, and the chatbot never touches it directly

The only database in this system is MongoDB, running in Docker, owned entirely by the existing Node.js/Express backend (AkshaV2-UIUX/backend). The Python chatbot has no database driver, no connection string, and no direct query — every fact it reports is fetched by calling that Node API, per the flow diagram below.

  • Conversation checkpoints — the architecture doc specifies a second, isolated Mongo database for this, but Phase 0 currently uses LangGraph's in-memory MemorySaver instead (documented stand-in — a one-line swap once wired up).
  • Help & Product Guide's document search is not a database at all — keyword/term-overlap scoring over two local markdown files (app/tools_help.py). No embeddings, no vector index, nothing Chroma- or FAISS-shaped is running today; FAISS is a named future upgrade, explicitly marked "NOT BUILT."

No collection here backs Live Monitoring or Insights & Analytics as a document store — Live Monitoring reads a live REST snapshot off the same Node routes, and per the architecture doc, insight/KPI data is file-based (local disk or Blob storage), not a Mongo collection.

The seven agents

Router picks exactly one per turn (or asks a clarifying question first). Multi-Language Support is deliberately not in this list — it's a formatter wrapper keyed on the request's language, not a routable agent.

AgentToolsData sourceNotes
Camera Operations get_cameras, get_camera_groups Node API Per-camera settings vs. group membership are two different tools — the router prompt is explicit about which owns which.
Alert Investigation get_recent_alerts, get_alerts_by_camera, get_cameras Node API Metadata only (camera, time, type) — no image content in Phase 1.
Live Monitoring get_live_cameras, get_spotlight_cameras Node API A REST snapshot, not a push feed — answers say "as of now," and the UI's Re-poll button re-runs the same query rather than auto-refreshing.
Insights & Analytics get_insight_report Node API Defaults to a 7-day window when the operator doesn't specify one, and says so.
Notification get_notification_config, get_group_notification Node API Read-only. Distinguishes "configured recipient" from "confirmed delivery" — no delivery-confirmation logs exist yet.
Help & Product Guide search_docs 2 local .md files Keyword/term-overlap scoring, not vector search. FAISS is the named future upgrade — not built.
Error & Status Explanation explain_error_or_status Static glossary No numeric ERR_xxx catalog exists — the agent is explicitly instructed never to imply one does.
