Aksha · Healthcare Vertical · Use-Case Plan

What's actually possible in a hospital with computer vision — and how

Every use case below is checked against two real constraints: whether the training data actually exists (per the companion dataset atlas), and whether Aksha's current detection pipeline — single-frame YOLO object detection, not pose estimation or action recognition — can plausibly deliver it without a new architecture.

Reading this plan: the three tiers are not a maturity ladder to climb in order — they're an honesty ladder. Tier A is safe to put on a roadmap today. Tier B is a real R&D commitment with named caveats. Tier C use cases are frequently the ones a hospital asks for first (falls, wandering, infant safety) — and are exactly where overpromising does the most damage.

Priority matrix — clinical criticality vs. technical feasibility

Where each use case sits once both axes are honest. The upper-right is the actual starting roadmap; the upper-left is where hospitals push hardest and where the technical gap is largest.

Tier A

Build now — same tech Aksha already ships

No new model architecture, no new dataset risk. Config/class additions to the existing YOLO detection + zone-alert pipeline.
Unauthorized-zone access — ICU, NICU, pharmacy, blood bank, drug cabinet
Why critical: patient safety, and pharmacy/blood-bank access is a regulatory requirement, not a nice-to-have.
HowZero new model work — the same person-detector + polygon-zone logic already running for perimeter/loading-bay intrusion, pointed at a new zone.
Person down / collapse on floor
Why critical: falls are a leading hospital adverse event, and unwitnessed collapse in a corridor is the highest-cost failure mode.
HowThe supine person class already exists in Aksha's trained model — this is a config change (add the class to ward/corridor camera alert rules), not new training. Add zone logic to distinguish "supine on a bed" (fine) from "supine on the floor" (alert).
Face mask compliance
Why critical: infection control, especially in isolation and immunocompromised-patient areas.
HowIdentical pattern to the existing helmet/no helmet class. Dataset already identified and commercially clean (Kaggle Face Mask Detection, CC0).
Fire / smoke — OT, oxygen storage, utility rooms
Why critical: life-safety; oxygen-tank fire risk is a standing hospital hazard.
HowReady-to-train public datasets already in YOLO format. Standard detection-class addition; adapt lighting/angle for ward and OT cameras.
Weapon detection at ED entrance
Why critical: a documented, real risk at emergency-department entrances.
HowBest-matched dataset in the whole atlas (~2,600 CCTV-angle images) — light fine-tuning on the actual entrance camera's angle and lighting.
Tier B

Real requirement, real R&D lift

Needs new classes trained on real hospital imagery, a licensing check, or an honest scope-down from what the name implies.
Ward / bed occupancy (empty vs. occupied)
The catch: generic "room occupancy" datasets don't capture bed-specific state — this needs a genuinely new class trained on real bed imagery.
HowCustom-labeled hospital footage for an empty-bed / occupied-bed classifier layered on top of existing person detection.
Broader clinical PPE — gown, gloves, face shield
The catch: ~24,900 images exist, but they're mostly construction-site PPE, not clinical attire.
HowRelabel a subset on real hospital imagery before training, or accuracy will silently degrade on gowns/shields that don't resemble a hard hat.
Hand hygiene compliance
The catch: the only real hospital-sourced dataset (WHO 6-step, PSKUS/EDI-RIGA) is academic-license-only, and true step-verification needs temporal action recognition — a different model family from Aksha's current single-frame detector.
HowShip a deliberately cruder v1: "did a person dwell near the dispenser for >N seconds," a zone + dwell-time proxy buildable on the current stack. State plainly to stakeholders that this is not step-by-step WHO compliance verification.
Aggression / violence detection — ED, psychiatric ward
The catch: needs action recognition over time, not bounding boxes; the only usable base dataset (RWF-2000) has no stated commercial license; false positives here carry real reputational and legal weight.
HowScope as a multi-month R&D track with its own model architecture — do not put this on a near-term feature roadmap.
Tier C

No honest CV-only answer today

Frequently what a hospital asks for first — falls-over-time, wandering, infant safety. This is exactly where overpromising causes the most damage.
Bed-exit / unattended-bed event
Why not: needs the on-bed → off-bed → exit transition labeled over time — no public dataset covers this, only static presence.
Reframe asa custom data-collection project: what footage, from where, under what consent process — before any modeling starts.
Wandering / elopement detection
Why not: dementia/ward-specific wandering has no released video data anywhere.
Reframe asgeneric person re-identification + time-in-zone logic — an engineering project on top of existing detection, not a new visual class, and still needs real evaluation data before deployment.
Infant abduction alert (NICU)
Why not: the entire industry solves this with RFID/tag hardware for good reason — the failure mode of a missed CV detection here is catastrophic.
Recommendationdo not pitch this as a CV feature. Position Aksha's camera layer as a complement to RFID (e.g., flag an unrecognized adult near a crib zone), never the primary safeguard.
Restraint-check compliance
Why not: no dataset addresses restraint checks or check-interval timestamps; in-bed monitoring datasets exist but don't cover this protocol.
Reframe asa custom capture-and-label project scoped with clinical staff to define what a "check" looks like on camera.
Prolonged immobility / pressure-ulcer prevention
Why not: needs continuous pose tracking over hours inside a patient room — a different technical stack from object detection, with no public dataset for the movement-over-time signal itself.
Reframe asa long-horizon R&D track; the SLP in-bed pose dataset is a possible base component, not a solution.
Nurse rounding compliance
Why not: only commercial RTLS/badge hardware products solve this today — no public vision dataset addresses room-entry/dwell-time-for-rounding.
Recommendationif this is a must-have, integrate with badge/RTLS data rather than building it from video.
Code Blue / response-time tracking
Why not: this isn't a vision problem — it needs event correlation between the alarm system and camera-detected staff arrival.
Reframe asa systems-integration project: alarm timestamp + person-detection timestamp in the same zone, not a new model.

The gate underneath Tier B and C

Every Tier B/C use case above lives in a patient room, ICU, or NICU — and continuous video surveillance there runs into consent and privacy law before it runs into a modeling problem: India's DPDP Act, hospital NABH accreditation norms, and the rough equivalent of HIPAA in other markets.

That gate needs clearing with the hospital's compliance/legal team before any of these gets pitched as a deliverable — it is a real requirement, not a footnote to add later.

Recommended rollout sequence

Sequencing by what's both clinically valuable and technically honest today, not by what a sales conversation asks for first.

01Now
Ship all five Tier A use cases
Config and class additions to the existing pipeline — unauthorized-zone access, person-down/collapse, mask compliance, fire/smoke, weapon detection. No new architecture, no dataset-license risk, fastest path to a working hospital pilot.
02Next
Scope Tier B with explicit downgrades stated up front
Ward/bed occupancy and clinical PPE relabeling are straightforward data-collection projects. Hand hygiene ships as a dwell-time proxy, named as such to the customer — not as WHO-step verification. Aggression/violence detection gets scoped as its own R&D track with a separate timeline, not bundled into the same release.
03Parallel track
Clear the regulatory gate before touching Tier C
Engage the target hospital's compliance/legal function on in-room camera consent (DPDP Act, NABH) in parallel with Tier A/B delivery, so it isn't a surprise blocker when a Tier C conversation starts.
04Only after 01–03
Treat each Tier C item as its own data-collection project
Wandering, bed-exit, restraint-checks, and prolonged immobility each need a bespoke capture-and-label effort defined with clinical staff — not a shared "advanced features" sprint. Infant abduction and nurse rounding should be positioned as hardware-led (RFID/RTLS), with vision as a complement at most.
